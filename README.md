# تسمياتي | بيئة الكتابة الذكية

تطبيق ويب عربي تفاعلي لتدريس مهارات الكتابة لطالبات الصف الأول الثانوي وفق استراتيجية «تسمياتي» بخطواتها السبع، مع مساعد ذكي موحد تتغير وظيفته بحسب النشاط، ولوحة للمعلمة، وملف إنجاز لكل طالبة.

## التشغيل السريع

المتطلبات: **Node.js 22.13 أو أحدث** (يستخدم التطبيق قاعدة SQLite المدمجة في Node، فلا يحتاج إلى خادم قاعدة بيانات منفصل).

```bash
npm install
npm run build
TEACHER_PASSWORD=كلمة-مرور-قوية npm start
```

ثم افتحي `http://localhost:3000`.

- إن لم تضبطي `TEACHER_PASSWORD` تُنشأ كلمة مرور عشوائية وتُطبع في سجل الخادم عند أول تشغيل.
- خطوات البداية: ادخلي بصفتكِ معلمة ← **المحتوى والحصص** ← عايني الحصة الأولى واعتمديها وأتيحيها ← **الطالبات والتقدم** ← أنشئي رموزًا دراسية ووزعيها.

## ربط المساعد بنموذج الذكاء الاصطناعي

يتصل المساعد بالنموذج **عبر الخادم فقط**؛ لا يصل المفتاح إلى المتصفح أبدًا. طريقتان:

1. من لوحة المعلمة ← الإعدادات ← أدخلي المفتاح واختاري المزود والنموذج ← «اختبار الاتصال».
2. أو بمتغير البيئة: `GEMINI_API_KEY` لـ Google Gemini (النموذج الافتراضي `gemini-3.8-flash`)، أو `ANTHROPIC_API_KEY` لـ Claude، أو `OPENAI_API_KEY` مع `AI_PROVIDER=openai` و`AI_BASE_URL` لأي مزود متوافق مع OpenAI.

دون مفتاح يعمل المساعد في **«وضع تجريبي غير متصل بالنموذج»**، ويُوسم بذلك صراحة في كل مكان: يعرض أسئلة النشاط بالتتابع ويسجل الإجابات، ولا يقيّمها، ولا يولّد ملاحظات تشخيصية.

## الحصص وفق دليل المعلم

الحصص التسع مبنية على **دليل المعلم** (البرنامج التعليمي القائم على استراتيجية «تسمياتي»)، ونصوصه منقولة حرفيًا: عنوان الحصة وفكرتها العامة وأهدافها، ومهارات الكتابة والمنتج الكتابي، ثم سبع مهمات مرقمة (مثل المهمة 1-1) واحدة لكل مرحلة من مراحل الاستراتيجية بترتيبها وزمنها (4، 6، 5، 5، 9، 11، 5 دقائق)، وفي كل مهمة أنشطتها بنصوصها الموجهة للطالبة، وإجراءات التنفيذ المرتبطة بالمعلمة وبالطالبة، ثم **النشاط المنزلي** بمهمتيه ومتابعة المعلمة.

- أنواع التفاعل كما يصفها الدليل: اختيار من متعدد مع تغذية راجعة لكل بديل، ومطابقة بالقوائم («اختاري من القائمة»)، وتصنيف في مجموعات، وترتيب، وجداول «أكتب هنا»، واختيار متعدد، و**أداة تصميم المخطط** (الجدول، وشجرة الذاكرة، وهيكل السمكة).
- الأزرار بأسمائها في الدليل: «تحقق من إجابتي» للفحص الموضوعي، وأزرار المساعد مثل «فحص اختياراتي» و«فحص مقدمتي» (تُرسل طلبها إلى المساعد مع تعليمات خاصة لا تظهر للطالبة)، و«تسليم المهمة» في الإنتاج المستقل، و«تحليل …» في التقويم، و«اعتماد موضوعي» في النشاط المنزلي.
- التقويم الذاتي بمستويي الدليل (متحقق / يحتاج إلى تحسين) ومعاييره، ثم التحليل الذكي، ثم النسخة المحسنة مع الاحتفاظ بالنسخة الأصلية.
- تبني كل حصة على منتج الطالبة السابق: بطاقة الموضوع ← بنك المعلومات ← بطاقة مراحل البناء ← بطاقة عناصر المخطط ← المخطط المتكامل ← العنوان والمقدمة ← فقرات العرض ← الخاتمة والنص المراجع ← الموضوع في صورته النهائية. لوحة «منتجاتي السابقة» وزر «استرجاع من منتجاتي السابقة» يتيحان البناء عليه.
- ما وصفه الدليل دون نصه (مثل نسختي الفقرة في المهمة 9-1، ورسائل المساعد الافتتاحية وأسئلته، والتغذية الراجعة لكل بديل) كتبه المطوّر، ويظهر للمعلمة في المعاينة بعلامة «مادة مقترحة للمراجعة»، وتظهر لها في المعاينة كذلك الإجابات المعتمدة.
- البنية السابقة للحصص محفوظة في `content/archive/v1-before-new-guide/`.

### تحديث الحصص من الدليل

`content/source/guide.json` نص الدليل مستخرجًا من ملف Word (`python3 scripts/parse-guide.py الدليل.docx content/source/guide.json`)، و`content/source/spec-L0N.mjs` مواصفات التفاعل لكل نشاط. يبني `npm run lessons` ملفات الحصص منهما، ويتحقق `npm run check-guide` من أن كل نص في الدليل موجود حرفيًا في الحصص وأن المهمات بترتيبه وأزمنته.

## سلالم التقدير والأسماء والتصفير

- **سلالم التقدير** (تبويب في لوحة المعلمة): تقدّر المعلمة كل طالبة في كل مهمة ونشاط منزلي وفق بنود مأخوذة من المهارات المعتمدة للنشاط (ومعايير الحصة في الإنتاج المستقل والتقويم)، مع ملاحظة. يمكن تعديل بنود أي نشاط، وتعديل المستويات (الافتراضي: ممتاز 4، جيد جدًا 3، جيد 2، يحتاج إلى دعم 1) من الإعدادات. التقدير حكم المعلمة وحدها: لا يملؤه المساعد الذكي، ولا يظهر للطالبات. يُصدَّر في ملف CSV مستقل.
- **التقارير** (تبويب في لوحة المعلمة): صورة عامة للصف (التقدم في الحصص، ومتوسط التقدير عبر الحصص، وتوزيع المستويات، وإتقان المهارات الثماني عشرة، وقائمة بمن تحتاج إلى متابعة)، وتقرير لكل طالبة (تطور تقديرها مقارنة بالصف، ونقاط القوة وما يحتاج إلى دعم، وملفها في المهارات، والخط الزمني لتقدمها: متى بدأت وسلّمت وحسّنت وأكملت كل حصة) قابل للطباعة. كل الأرقام من تقديرات المعلمة وسجل الإنجاز فقط، ولكل رسم جدول بيانات بديل.
- **الأسماء**: يمكن للمعلمة إضافة الطالبات بأسمائهن (اسم في كل سطر) أو برموز مستعارة فقط. يظهر الاسم للمعلمة وللطالبة نفسها فقط؛ ويبقى الاسم المستعار للزميلات، ولا يُرسل الاسم إلى النموذج، ولا يدخل ملفات التصدير إلا باختيار صريح.
- **التصفير** (الإعدادات): «تصفير عمل الطالبات» يُبقي الرموز والأسماء ويمحو العمل، و«حذف جميع الطالبات» يحذف كل شيء. يتطلبان كلمة مرور المعلمة وكتابة «تصفير»، ولا يمسّان المحتوى أو الإعدادات.

## نسخة المعاينة

`node scripts/build-preview.mjs` يبني ملف HTML واحدًا يشغّل التطبيق كاملًا داخل المتصفح (البيانات في المتصفح فقط، والمساعد في الوضع التجريبي). يُستخدم للاستعراض والمراجعة، لا للتطبيق الميداني.

## النشر

دليل النشر المجاني (Render + Turso) ثم المدفوع: **DEPLOY.md**.

عند ضبط `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` تُنسخ كل كتابة إلى قاعدة Turso السحابية وتُستعاد منها عند بدء التشغيل، فلا تضيع البيانات على الاستضافات التي تمسح القرص.


التطبيق خادم Node واحد يخدم الواجهة والواجهات البرمجية معًا، ويحتاج إلى **قرص دائم** لملف قاعدة البيانات.

- **Docker:** `docker build -t tasmiyati . && docker run -p 3000:3000 -v tasmiyati-data:/data -e TEACHER_PASSWORD=... -e ANTHROPIC_API_KEY=... tasmiyati`
- **Render / Railway / Fly.io / خادم VPS:** أمر البناء `npm install && npm run build`، وأمر التشغيل `npm start`، مع ربط قرص دائم وضبط `DATA_DIR` عليه.
- استخدمي **HTTPS** في النشر الفعلي (تُضاف علامة Secure إلى ملف تعريف الجلسة تلقائيًا خلف وكيل HTTPS).
- لا تصلح الاستضافات الثابتة وحدها (مثل GitHub Pages) لأن التطبيق يحتاج إلى خادم وقاعدة بيانات.
- النسخ الاحتياطي: انسخي ملف `data/tasmiyati.db` دوريًا.

```
  strategy.json       الخطوات السبع
  skills.json         المهارات الثماني عشرة (الصياغة المعتمدة + صياغة مبسطة للطالبة)

  assistant-rules.json القواعد الإلزامية للمساعد
  lessons/            الحصص التسع (63 مهمة و9 أنشطة منزلية)، مولّدة من الدليل
  source/             نص دليل المعلم ومواصفات التفاعل لكل نشاط
  archive/            نسخة احتياطية من البنية السابقة
  AUTHORING.md        دليل إعداد حصة جديدة
server/             الخادم (Node + node:sqlite، بلا اعتماديات تشغيل)
  ai.ts               بناء تعليمات المساعد من بيانات النشاط والاتصال بالنموذج
  logic.ts            التقدم وضبط الانتقال والإنتاج المستقل والتقويم
  routes-*.ts         واجهات الطالبة والمعلمة
shared/types.ts     الكيانات: Lesson, StrategyStage, Activity, Rubric, AIConfiguration...
web/src/            الواجهة (React + TypeScript)
tests/              اختبارات التكامل
```

### لماذا هذه الاختيارات التقنية؟

- **React + TypeScript** للواجهة كما طُلب، مع **esbuild** للبناء (سريع وبلا إعدادات معقدة).
- **CSS مكتوب يدويًا بمتغيرات تصميم** بدل Tailwind: الواجهة RTL بالكامل ومتجاوبة، ويقل حجم الاعتماديات.
- **خادم Node دون إطار** و**SQLite المدمجة**: لا اعتماديات تشغيل إطلاقًا، فيسهل النشر في مدرسة أو جامعة ويقل سطح الثغرات.

## حماية البيانات

- لا تُجمع أسماء حقيقية؛ معرفات دراسية مستعارة وأسماء عرض مثل «طالبة 01».
- صلاحيات منفصلة: الطالبة لا تصل إلى لوحة المعلمة ولا إلى بيانات زميلاتها، ولا يُنشر أي عمل إلا بموافقة المعلمة.
- اطلاع المعلمة على سجل المساعد يُسجَّل في سجل تدقيق.
- تصدير البيانات (CSV / JSON) وحذف بيانات أي طالبة نهائيًا من لوحة المعلمة.
- لا يُرسل إلى النموذج إلا سياق النشاط الحالي وإجابات الطالبة فيه، دون معرفها. راجعي شروط مزود النموذج بشأن استخدام البيانات في التدريب وأعمار المستخدمين قبل التفعيل.
